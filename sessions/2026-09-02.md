2. **`feat: add recordCheck reporting, fix test.fixme(title,fn) bug, retrofit all specs`**
   - New `recordCheck(testInfo, {label, expected, actual})` helper in `tools/artifact-helpers.js` —
     additive (call alongside `expect()`, never replaces it). `report.md` now renders a
     `Check | Expected | Actual` table for every test that uses it: inline for failures, in a new
     collapsed-by-default "What Each Passing Test Checked" section for passes.
   - **Real bug found and fixed**: `test.fixme('title', asyncFn)` (the static 2-arg form) **never
     executes its body at all** — confirmed empirically. This meant the reason text for every
     blocked AC was structurally unrecoverable from any test run, not just missing from the old
     report format. Fixed by switching to the inline form: `test.fixme(true, 'reason')` called as
     a statement inside a normal `test()`, after pushing the `acceptance-criteria` annotation.
     Applied to all 3 affected tests (`create-a-new-business-quote-v1.spec.js` AC01,
     `select-default-commission-category-v1.spec.js` AC16 and AC12). New "Skipped / Blocked Tests
     — Detail" report section surfaces the reason.
   - **190 `recordCheck` calls retrofitted** across all 13 modern (`expect()`-based) spec files —
     dispatched as 13 parallel agents, one per file, then independently syntax-verified and
     live-verified end to end.
   - Both conventions are now **mandatory** (not optional) for new specs going forward — documented
     in `.kiro/steering/test-expansion-process.md` and `TEST-GENERATION-PROCESS.md` Step 4.
   - Added a 7th mandatory item to the input-correctness checklist: any field/AC with a stated
     numeric/length/date limit must be tested at 3 points (below/at/over), not one arbitrary value.

4. **`fix: close boundary-value test coverage gaps, fix a wrong assertion (KID-12)`**
   - Full audit (fresh research agent) of every documented limit vs. actual test coverage found 6
     genuine gaps (one claimed gap — a "$500 minimum for Specific Injury" — turned out to be

     65), `KID-10` (kids free-tier $50k threshold), `PREM-26` (M&L bundling threshold — probed to
     exactly **$1,000/mo**, confirming the doc's "likely $1,000/mo" guess).
   - **`KID-12` was actively WRONG, not just untested.** The existing test asserted a stale
     ~21-year DOB window the doc itself said was "corrected" to 64 years on 2026-08-26. Live
     disambiguation (reading the kid DOB field side-by-side with the KNOWN adult DOB field, same
     page state) proved the 2026-08-26 "correction" was itself the mistake — most likely that
     investigation read the adult's own field by accident. The kid field genuinely IS a ~21-year
     window; both the test and `kids-cover-and-multi-life/page.md` are corrected back, computed
     relative to "now" so neither goes stale as the year changes.
   - Technical discovery worth remembering: **typing a single REPEATED character via
     `page.keyboard.type()` loses almost everything typed** (`'A'.repeat(19)` → only 2 characters
     landed, regardless of typing strategy tried), while varied/cycling characters land correctly
     every time. Use a varied-character generator for any test typing a long string into a plain
     text field — see `variedChars()` in `personal-details.spec.js`.
