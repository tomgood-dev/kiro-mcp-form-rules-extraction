### Test Console Constraints (documented in `docs/test-console-authoring-guide.md`)

- One `test()` per file
- Each test logs in fresh and signs out at end
- Only run one test at a time (single session per user)
- ES5 syntax inside `page.evaluate()` blocks (no arrow functions, no spread, no template literals)
- No UTF-8 BOM
- `throw new Error('message')` for readable failure output
- Version filenames on every update (Test Console caches old files)
- Build combined files incrementally from working files (not from scratch)

### Key Technical Findings

- OutSystems Test Console Forge Plugin runs each file in parallel with fresh browser
- Cannot share state between tests
- `test.describe.configure({ mode: 'serial' })` is ignored
- `page.evaluate()` must use ES5 syntax (function(){}, var, Array.from)
- Screenshots only show inline for Playwright timeout errors, not for throw/expect failures
- Login sessions are single-user — concurrent logins with same credentials get rejected
- The `window.open` interception pattern works: evaluate → capture URL → navigate
- Calc-mask fields need digit-by-digit entry with Backspace clearing
- Cover buttons need evaluate-based `.click()` (standard Playwright click misses XHR)
