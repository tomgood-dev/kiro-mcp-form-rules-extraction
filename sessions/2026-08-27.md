## Decisions locked in for the generation pipeline

1. **Approach:** Start **fully automated**, work backwards to semi-automated only where something
   genuinely blocks it. The point is to find the *real* friction (expected: selector discovery on
   the OutSystems DOM, ambiguous ACs).
2. **Harness:** A **sub-agent pipeline** (not inline), so it's a reusable capability. Its prompt
   MUST reference our existing conventions rather than reinventing them:
   - `.kiro/steering/test-expansion-process.md` (report.md convention, AC annotation format,
     parallel/serial test structure, probe-safety rules, verify-before-reporting discipline)
   - `.kiro/steering/project-context.md` (app URLs, DOM facts, where things live)
   - `DELTA-UPDATE-PROCESS.md` (canonical AC format + our own stable internal IDs)
   - `apps/asteron-quote-apply/helpers/` (reuse existing interaction helpers, don't rebuild)
   - `tools/server.js` (exploration server for selector discovery)
   - `playwright.edge.config.js` + `apps/asteron-quote-apply/global-setup.js` (run/auth — Edge
     channel, msedge; global-setup already fixed)
3. **Decision log (heavily monitored):** the sub-agent records EVERY meaningful decision — right
   and wrong — for later refinement. Structure:
   - Per-run detail: `apps/asteron-quote-apply/test-runs/<spec-slug>/generation-log-<timestamp>.md`
     (extraction choices, selectors found, ambiguities + how resolved, deferrals + reasons,
     failures + fallbacks)
   - PLUS a rolled-up cumulative lessons file (create at repo level, e.g.
     `TEST-GENERATION-LEARNINGS.md`) that grows over time.
4. **Credentials:** use the normal test creds (BASE_URL / ASTERON_LOGIN_EMAIL /
   ASTERON_LOGIN_PASSWORD) — pass through to the sub-agent. Login/session already solved.
5. **Autonomy:** run **end to end without pausing** the first time (generate → probe → run →
   report), logging decisions verbosely; we review the log after. Fall back to gated pauses only
   if the first run goes badly.
6. **Target:** a NEW user story (Tom to drop into `apps/asteron-quote-apply/docs/user-stories/`),
   targeting the **same Quote & Apply screen** — so the app is reachable and selector discovery is
   the real test.
