## Playwright MCP Setup

### Config file: `D:\Users\TOMGOO\Documents\QuoteAndApply\.kiro\settings\mcp.json`
```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx.cmd",
      "args": [
        "@playwright/mcp",
        "--browser", "msedge",
        "--ignore-https-errors"
      ],
      "env": {
        "NODE_TLS_REJECT_UNAUTHORIZED": "0"
      }
    }
  }
}
```

### Why these options:
- `npx.cmd` — Windows requires `.cmd` extension (PS execution policy blocks `.ps1` scripts)
- `--browser msedge` — SSO login works because the managed work account is signed into Edge
- `--ignore-https-errors` — corporate proxy uses a custom CA cert
- `NODE_TLS_REJECT_UNAUTHORIZED=0` — same reason, for Node-level TLS

### What Playwright MCP gives us (tools available in Kiro):
- `browser_navigate` — go to URL
- `browser_click` — click element by text/ref
- `browser_type` — type into input
- `browser_snapshot` — get accessibility tree (structured page state)
- `browser_select_option` — select dropdown value
- `browser_tab_list`, `browser_tab_new`, etc.
- No HTTP middleman, no timeouts, no crashes

### Headed mode:
Playwright MCP is headed by default (no `--headless` flag). Edge window will open.
User needs to manually complete SSO login, then Kiro can drive the browser.

## Troubleshooting — If Playwright MCP Doesn't Work

### Problem: MCP server not loading / not initialized
**Check**: Run `/mcp` in Kiro chat to see server status.
**Possible causes**:
1. `npx.cmd` not in PATH → need to add `C:\Program Files\nodejs` to system PATH or use full path in config
2. Package not cached → first run downloads `@playwright/mcp@0.0.79`, may fail behind proxy
3. Edge not installed → unlikely on this machine, but check

**Fix for PATH issue** — change config to use full path:
```json
{
  "mcpServers": {
    "playwright": {
      "command": "C:\\Program Files\\nodejs\\npx.cmd",
      "args": [
        "@playwright/mcp",
        "--browser", "msedge",
        "--ignore-https-errors"
      ],
      "env": {
        "NODE_TLS_REJECT_UNAUTHORIZED": "0"
      }
    }
  }
}
```

**Fix for proxy/download issue** — pre-install the package:
```powershell
$env:Path = "C:\Program Files\nodejs;" + $env:Path
$env:NODE_TLS_REJECT_UNAUTHORIZED = "0"
cd "D:\Users\TOMGOO\Documents\QuoteAndApply\kiro-mcp-form-rules-extraction-master"
npm.cmd install @playwright/mcp
```
Then change config to use local install:
```json
{
  "mcpServers": {
    "playwright": {
      "command": "node",
      "args": [
        "D:\\Users\\TOMGOO\\Documents\\QuoteAndApply\\kiro-mcp-form-rules-extraction-master\\node_modules\\@playwright\\mcp\\cli.js",
        "--browser", "msedge",
        "--ignore-https-errors"
      ],
      "env": {
        "NODE_TLS_REJECT_UNAUTHORIZED": "0"
      }
    }
  }
}
```

### Problem: Browser launches but SSL errors / can't reach site
**Fix**: Ensure both `--ignore-https-errors` AND `NODE_TLS_REJECT_UNAUTHORIZED=0` are set.

### Problem: SSO login doesn't work (redirects to Microsoft login that fails)
**Cause**: Edge launched by Playwright doesn't share the system Edge profile by default.
**Fix**: Add `--user-data-dir` pointing to the Edge profile, OR user logs in manually each time.
The user-data-dir for Edge is typically:
`C:\Users\TOMGOO\AppData\Local\Microsoft\Edge\User Data`
But sharing a profile with a running Edge instance causes conflicts. Better to just log in manually.

### Problem: "execution policy" errors
**Cause**: PowerShell blocks `.ps1` scripts. `npx` is a PS script, `npx.cmd` is not.
**Fix**: Config already uses `npx.cmd`. If that still fails, use the full `node` + `cli.js` path approach above.
