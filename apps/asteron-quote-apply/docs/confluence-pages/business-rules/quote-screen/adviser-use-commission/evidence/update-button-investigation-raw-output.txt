Conclusion from Run C: with genuinely zero interaction, the button never auto-enables.
It does not "become enabled over time" on its own. This rules out a timing/async-render
explanation and points at Run A's own mouse.wheel(0, 400) call as the contaminating step
(a plausible mechanism: an OS/browser quirk where a wheel event over a focused <select>
changes its value, which the underlying OutSystems reactive binding may pick up as a
genuine change even though no test code intentionally selected anything).
